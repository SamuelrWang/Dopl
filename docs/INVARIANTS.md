## 1. Layout & file size

- **Feature-first.** `src/features/<name>/` owns its UI, hooks, types, `server/`. No cross-feature imports — shared things go to `src/shared/`. Never a top-level `lib/` or `components/` under `src/`.
- **Hard cap 500 lines, lint-enforced at `error`.** `eslint.config.mjs › "max-lines"` = `{max:500, skipBlankLines:false, skipComments:false}` over **three globs: `src/**`, `packages/*/src/**` AND `apps/*/src/**`** — the SPA is capped too, on the same block. **Both `skip*` false — every physical line counts.** "It's mostly comments" is not an argument for an exemption.
- **A file at 500 cannot absorb a COMMENT.** Correcting a stale docblock in an at-cap file is a split, not a doc fix.
- **Exemptions are a closed list in `eslint.config.mjs` carrying "DO NOT ADD TO THIS LIST — split the file instead."**
- **Measured 2026-08-11: exactly FOUR files exceed 500 in `src/`+`packages/`, and the exemption list names exactly those four.** Two are carve-outs (`src/shared/supabase/types.ts` generated; `src/features/knowledge/server/seed-fixtures-data.ts` data table); the real backlog is `billing/components/upgrade-modal.tsx` and `billing/server/webhook-handler.test.ts`. Re-measure, never quote — and use THIS form, which prunes `node_modules`/`dist` and drops `wc`'s `total` row:
  ```
  find src packages \( -name node_modules -o -name dist \) -prune -o \( -name '*.ts' -o -name '*.tsx' \) -print | xargs wc -l | awk '$1>500 && $2!="total"'
  ```
  ⚠ **The naive `find src packages -name '*.ts' -o -name '*.tsx' | xargs wc -l | awk '$1>500'` returns 73 rows, not 4** — the unparenthesized `-o` loses the path restriction, so it sweeps `node_modules` and the committed `dist/`, and `xargs` splits into batches that each emit their own `total`. A verification command that over-reports is worse than none: it trains you to ignore it.
- **Carve-outs (justify at top of file):** generated code, dense type-only files, pure data/config tables, and a single-function switch reducer that is one coherent state machine.
- **`dopl-desktop-app/` and `scripts/` are outside the root config.** The desktop has its own `eslint.config.js`, same rule, same severity, **zero exemptions**. `test/live/**/*.js` is its own block — the `.js` extension is load-bearing, it keeps that tier out of `node --test 'test/**/*.mjs'`.
- **Desktop runs with no headroom. Measured 2026-08-11: four `main/` files sit at EXACTLY 500** — `ui-sync.js`, `session-reducer.js`, `session-profiles.js`, `session-engine.js` — **and two more at 499** (`mcp-config.js`, `auth-tokens.js`), i.e. one line of room each. Nothing in the desktop tree is over. `test/eslint-config-coverage.test.mjs` asserts (via ESLint's own `calculateConfigForFile`) that every desktop file resolves to the cap.
- **Split by responsibility, layer, or sub-feature** — one file per reason to change. For `op`-dispatched MCP tools the pattern is fixed: the original stays the thin **registrar** (schemas + `op` routing) and delegates to `<tool>-ops-read/-write/-admin.ts`, shared resolvers in `<tool>-shared.ts`/`-render.ts`. Keep the re-export barrel if callers import through it.
- **A split scheduled on a line count waits indefinitely; a split scheduled by a new reason-to-change lands the same day.**

## 2. Data layer — repository / service / handler

- **Three layers.** `server/repository.ts` = pure data access, one function per query, **takes** a `SupabaseClient` (never creates one). `server/service.ts` = business logic, throws domain errors. `server/dto.ts` = `snake_case`→`camelCase`. `server/errors.ts` = error classes.
- **No `snake_case` key leaks past `repository.ts`.**
- **Every workspace-scoped query is filtered by `workspace_id` at the repository.** This holds even where the read runs as service role — **service role bypasses RLS entirely**, so on that path the service IS the fence and RLS is not a backstop.
- **A route handler is ≤80 lines and thin.** Pages never talk to Supabase; an RSC and its API twin read the same service code so they cannot drift.
- **A DTO carrying PII needs an ENTITLEMENT decision, not just a shape decision.** The viewer is a DTO INPUT: `channels/server/dto.ts › mapMemberRow` takes `viewerUserId` and scrubs private fields to the caller's own row.
- **Per-member settings are private BY COLUMN PRIVILEGE — not by policy, not by the DTO.** RLS filters ROWS; the requirement is a COLUMN. `channel_members` has `SELECT` revoked from `anon`/`authenticated` with a per-column `GRANT` of public columns only; `agent_tool_profile` is service_role-only, which binds PostgREST and realtime frames both. **Standing rule for any NEW per-member setting: add it to the DTO scrub AND leave it out of that migration's `GRANT` list. Two edits; the second is the one that binds.** Keep the scrub — it shapes the API response, where the server reads as service role and the column privilege redacts nothing.
- **Errors: throw, don't return tuples.** Convert at the boundary. The three real pieces are `src/shared/lib/http-error.ts › HttpError` (the class, and `toResponseBody()` is the ONE place the envelope shape is decided), `shared/api/parse-json.ts › parseJson`, and the shared catch-block helper `shared/api/http-error-response.ts › toHttpErrorResponse(source, err, mapDomainError?)` — imported by ~53 modules. Four feature wrappers delegate to it with their own domain mapper (`toKnowledgeErrorResponse`, `toChatErrorResponse`, `toSkillErrorResponse`, `channels/server/http-mapping.ts › toChannelErrorResponse`). Never a raw error string or a stack trace.
  - ⚠ **There is NO `withErrorHandler` and no `shared/api/error-handler.ts`** — that pairing has never existed in this repo. It is a docs-only fiction that lived in ENGINEERING.md for months and was copied into this file's first draft; `scripts/check-doc-refs.mjs` now resolves `path › symbol` anchors specifically so this class of claim cannot be written again. Conversion is a **catch block calling `toHttpErrorResponse`**, not a wrapper composed around the handler.
- **A NEW route uses the NESTED envelope — `{ error: { code, message, details? } }`** — because that is what `HttpError.toResponseBody()` returns and what every `toHttpErrorResponse` path emits. **The FLAT `{error, message, workspaces?}` shape in §4 is workspace RESOLUTION only**, surfaced verbatim by `@dopl/client`; it is a legacy surface with clients parsing it, not a second option to pick from. Two shapes exist; only one is choosable.
- **Never send `Cache-Control: no-transform`.** It forbids intermediaries applying a content coding — an instruction NOT to compress, not a stronger `no-cache`. What an SSE route needs is `X-Accel-Buffering: no` (`shared/api/sse-keep-alive.ts`).

Why/history: ENGINEERING.md §3, §8, §12.

**The wrappers that EXIST** (`grep -rn "^export function with" src/shared/auth/`, verified 2026-08-11):

| Symbol | File | What it does |
|---|---|---|
| `withUserAuth(handler)` | `shared/auth/with-auth.ts` | OAuth bearer (`dopl_at_*`) OR session cookie; injects `{userId, agentTokenId?, apiKeyWorkspaceId?, params}`; logs 5xx |
| `withMcpAccess(action, handler)` | `shared/auth/with-auth.ts` | Composes `withUserAuth`; paywall-gates MCP callers, logs analytics |
| `withWorkspaceAuth(handler, opts)` | `shared/auth/with-workspace-auth.ts` | Composes `withUserAuth`; resolves workspace fail-closed, verifies membership + `meetsMinRole`. **Default for workspace-scoped content routes.** |

| `requireCronSecret(request)` | `shared/auth/require-cron-secret.ts` | Bearer gate for `/api/cron/*`; fail-closed 503 when unset |

⚠ **`withExternalAuth` and `withAdminAuth` DO NOT EXIST** — **zero hits in `src/` + `packages/`**, verified 2026-08-11. Not "zero hits repo-wide": four DOC mentions survive, and all four are correct in place — `ENGINEERING.md:500` (**corrected 2026-08-11 in this same batch**; it now names the fiction as a fiction and points here), `docs/CLEANUP.md` (a dated capture, describing the tree as it was), and this line. **ENGINEERING no longer asserts these wrappers exist; do not "fix" it again.** Do not import or "restore" them, and do not invent a `requireUser` either.

- **Service-layer gates:** `features/workspaces/server/authz.ts › requireWorkspaceRole` (the one membership-fetch+role-check helper) and the pure hierarchy in `features/workspaces/member-policy.ts`, shared with the members UI.
- **Two caller-type options, orthogonal to `minRole`. Cookie/session callers authenticate AS the human and are NEVER gated by either — these only constrain OAuth tokens.**
  - **`writeScopeExempt` (default: gate ON).** OAuth bearer on any non-`GET` without `dopl.write` → 403 `WRITE_SCOPE_REQUIRED` + `WWW-Authenticate: insufficient_scope`.
  - **`sessionOnly: true`.** Rejects ALL OAuth tokens (403 `SESSION_REQUIRED`) regardless of scope — destructive, credential-minting, or permission-mutating routes an agent must never reach.
- **THE EXECUTABLE AUTHORITY IS `src/shared/auth/write-gate-coverage.test.ts`, NOT PROSE.** It pins **three** sets: `writeScopeExempt`, method-level `sessionOnly`, and field-level `SESSION_ONLY_FIELDS`. Adding a destructive route without `sessionOnly`, or narrowing any set, fails the suite. **Re-count, never amend by memory:** `grep -rl "sessionOnly: true" src/app/api | wc -l` → **20 route files, 2026-08-11**.
- **Granularity is per-METHOD by default** — the `GET`s on the channels consent/trust/members routes are deliberately ungated; polling and reading decide nothing.
- **THE RULE: gate the METHOD by default; gate the FIELD when the method carries writes an agent may legitimately make.** The one field gate is `src/app/api/channels/[channelId]/route.ts › SESSION_ONLY_FIELDS = ["visibility"]`. **A field gate is invisible to the method-level tripwire**, so the coverage test separately asserts the file set is exactly that route, that the constant names `visibility`, that the handler reads `auth.agentTokenId`, and that it throws `SESSION_REQUIRED` — a constant nothing reads would satisfy a file list while gating nothing. **A second field-gated route is a conscious edit to that test.**
- **`PATCH /channels/[channelId]/members` is `sessionOnly` because the agent tool profile is a CONTAINMENT control, not a preference** — the setting relied on for containment must not be writable by the thing it contains, durably. Per-method and per-field coincide there only because `agentToolProfile` is the sole field it carries. **Do not generalize to the next route — check what else the method writes.**
- **Rate limiting: ONE budget, both doors.** `withUserAuth`'s bearer branch limits on the same subject the MCP transport uses (`mcp:<tokenId>`), so a token has one budget across `/api/mcp` and every REST route. It runs **before** the sessionOnly/write-scope gates, so requests that would 403 still spend budget. Fail-closed: DB error → 429. Sessions never enter this branch. `/api/oauth/register` and `/token` carry per-IP limits (`shared/auth/oauth-rate-limit.ts`).
- **Bearer Supabase JWTs are SESSION callers.** `withUserAuth` routes by exact prefix: `dopl_at_*` → agent branch; anything else is verified locally as a Supabase JWT with cookie-identical semantics (the bundled SPA authenticates this way). **Never key agent-vs-user behavior off "has an Authorization header" — key off `agentTokenId`.**
- **Middleware verifies locally, never over the network.** `src/proxy.ts` must not call `supabase.auth.getUser()`; use `getClaims()` (local JWKS verification). Two traps, pinned by `proxy.test.ts`/`proxy-claims.test.ts`: `getClaims()` can throw a plain `Error` (not an `AuthError`, so not converted — wrap it, treat a throw as no session), and **cookie refresh depends on calling it with NO argument** (that path runs `getSession()` first, rotating near-expiry cookies onto the response).
- **`config.matcher` in `src/proxy.ts` is an auth boundary written as a negative lookahead.** A path may be excluded only if *nothing below the auth call can change what it does*. Two easy-to-miss failures: a public but **session-AWARE** path fails it, and so does one whose only interaction is the **Supabase cookie refresh** (dropping it shortens sessions). Pinned by `proxy.test.ts` section 6, which compiles the real exported matcher and asserts both directions.

Why/history: ENGINEERING.md §9, §9.1, §9.4.

## 4. Workspace resolution — fail-closed

`features/workspaces/server/service.ts › resolveActiveWorkspace(userId, headerWorkspaceId)` is THE resolver behind `withWorkspaceAuth` and `GET /api/workspaces/me`:

1. **API-key workspace lock** (in `withWorkspaceAuth`, before the resolver) — a contradicting target → 403 `API_KEY_WORKSPACE_MISMATCH`. Dead scaffolding today; preserved, not advertised.
2. **`X-Workspace-Id` header — UUID only.** Blank or non-UUID (a slug) → 400 `WORKSPACE_INVALID`. Never coerced to "no header", never a 500. `withWorkspaceAuth({workspaceIdFromQuery:true})` lets `?workspaceId=` slot in at the same priority (header wins if both) — that option exists for header-less `<a download>` export routes.
3. **No header → active memberships:** exactly one auto-targets; **0 or 2+ → 400 `WORKSPACE_REQUIRED`**.

- **There is NO silent default-workspace fallback.** `findDefaultWorkspaceForUser` is oldest-OWNED and is **forbidden in auth resolution** — signup-bootstrap + billing-grandfather only.
- **404 ordering is load-bearing.** A missing workspace answers before membership is judged, so "not a member" and "does not exist" stay indistinguishable and existence is never an oracle. The two reads run in parallel.
- **Envelope is flat `{error, message, workspaces?}`**, surfaced verbatim by `@dopl/client` and the web `apiRequest`. `WORKSPACE_REQUIRED` lists `{name, slug, role}` per membership.
- **Any UI reading a workspace-scoped route MUST send the header** (`apiRequest({workspaceId})`) or the fetch fails closed for multi-workspace users.
- **A boot endpoint never guesses a workspace.** `POST /api/boot` with `{segment}` resolves THAT segment and nothing else; with no body it takes the documented provisioning path, gated on onboarding, idempotent — **200, never 201**.

Why/history: ENGINEERING.md §9 (Workspace resolution), §7.

## 5. Channels — core model

> A **CHANNEL** (or DM) holds many **THREADS**.
> A **THREAD** is ONE exchange between two members about one thing — a single message or a long piece of work. It is SHARED: both members see the same thread, title, and status.
> A **SESSION** is ONE member's agent run working a thread, on THAT member's machine. Each side has its own. A session pauses and resumes; a thread does not. You never see the other member's session, only the messages it sends.

Inside a member's own window there is exactly ONE session, so it never needs a qualifier — **never write "agent session" or "channel session" in UI copy.**

- **`task` == `thread` at the storage boundary, deliberately.** DOMAIN name is `thread` everywhere a human or agent reads (`ChannelThread`, `thread-panel.tsx`, `useChannelThreads`, the MCP ops). STORAGE name stays `task`: the `channel_tasks` table, the `metadata.taskId`/`taskMode`/`taskCreatedBy`/`taskTitle`/`taskTarget` wire keys, the `task_*` kinds, the `TASK_*` codes, the `/tasks/**` route paths. A boundary comment marks the mapping in each crossing file.
- **`seq` IS NOT PER-CHANNEL.** The identity sequence lives on the TABLE, so one global counter serves every channel in every workspace: globally unique, strictly increasing per channel but **GAPPY**. **A seq RANGE is never a message count**, and **a cursor is only ever a number the server HANDED you** — never guessed.
- **Serialized append.** All inserts go through the `channel_message_insert` RPC (service-role EXECUTE only), which takes a per-channel `pg_advisory_xact_lock` **before** the insert, so `seq` commits in strict monotonic order — no committed-out-of-order hole a reader could poll past. Every writer uses it, the cron sweep included.
- **Channels RLS is stricter than the older tables:** INSERT/UPDATE/DELETE REVOKEd from `authenticated`+`anon`, write policies dropped — **every write is service-role-only through the feature service.** Member SELECT remains for reads and feeds the publication.
- **ADDRESSING IS REQUIRED IN A GROUP CHANNEL — an unaddressed ask triggers NOBODY.** The implicit trigger fires only on a **known-exact `memberCount === 2`** plus explicit membership; at 3+ a message classifies `fyi` or `ignore`. **Fail-closed BY DESIGN. Never add a broadcast trigger** — it converts the loop brake into a storm and mass-prompts operators who were never asked for anything. `GROUP_CHANNEL_MIN_MEMBERS = 3` in `features/channels/constants.ts`, deliberately duplicated in `packages/mcp-server/src/tools/channel-addressing.ts` (no shared source tree), pinned together by `channel-addressing-rule.test.ts`.
- **The web states the rule in exactly two places** (`channels/components/message-composer.tsx`, **`channels/components/invite-dialog.tsx` — the CHANNELS one**); **the MCP lane in exactly one** (`channel-addressing.ts`). ⚠ **`invite-dialog.tsx` is an ambiguous basename: `members/components/invite-dialog.tsx` also exists and states nothing about addressing.** Anything else implying an unaddressed channel message reaches an agent is wrong — **"broadcast" is not a shape this product has.**
- **THE LOOP BRAKE: an UNADDRESSED agent-authored message can never trigger, at any N** (`dopl-desktop-app/main/targeting.js › classify`). Member-count-independent.
- **Because the trigger keys on a COUNT, the roster is a BEHAVIOUR.** One ghost `channel_members` row turns a live 1:1 into a "3-party" room and silently disables the implicit trigger — no error, no signal. A workspace departure REMOVES the row (`workspaces/server/membership-admin.ts › removeMember` → `channels/server/service-workspace-departure.ts`), best-effort, always AFTER the membership delete.
- **TERMINATION IS A ROW DELETE, NOT A STATUS FLIP.** Nothing writes `workspace_members.status` to anything but `'active'`; no self-serve leave route, no deactivation. "No longer active" and "has no row" are the same statement. **Adding a deactivated state would silently break the departure sweep and its backfill, neither of which fails loudly.**
- **A thread is one requester + one target.** Reads are channel-visible (a third member CAN read a pair's thread; deliberate). Writes → **403 `TASK_FORBIDDEN`** unless the poster is `created_by` or `target_user_id` (`isThreadParticipant`, synchronous — a threaded post costs no participant query). A legacy `task-{channelId}-{seq}` id is validated against its opening message's `{author, to_user_id}` pair, and a non-participant's tag is **SILENTLY STRIPPED, never 403'd** (installed desktops post legacy ids for lifecycle events).
- **A thread may not be addressed to its own creator** — 400 `CHANNEL_TASK_SELF_TARGET`, checked AFTER the addressee-membership check and BEFORE the idempotency short-circuit (behind it, a retry returns the stored dead thread as a success).
- **Reserved metadata is STRIPPED from caller input and re-stamped only from validated fields**, at the single point `channels/server/service-writes-metadata.ts › resolvePostMetadata`. ⚠ **THE LIST LIVES IN CODE — read the `delete metadata.*` run in that function plus `service-writes-metadata-markers.ts` before trusting any prose copy, this one included.** As measured 2026-08-11 it is:
  - **Stripped, then re-stamped from a server or validated source:** `to_user_id`, `summary`, `runtime`, `appVersion`, `session_id`, `intent`, `handoff`, and the four task keys (`taskMode`/`taskCreatedBy`/`taskTitle`/`taskTarget`).
  - **Stripped and NEVER re-stamped** (no writer left; the strip is what keeps them unforgeable): `to_user_notify`, and the three dead agent-attribution keys `to_agent_id`/`to_agent_ids`/`author_agent_id` — **kept in the strip list with no writer left, because stored rows still RENDER them**, so a caller able to set one could attribute their own words to somebody's retired agent.
  - **The markers**, from `service-writes-metadata-markers.ts`: `CLOSE_PROPOSAL_KEYS` = `closeProposed`/`closeOutcome`, `REOPEN_MARKER_KEY` = `threadReopened`, and **`CALM_FLAG_KEYS` — SIX, not five**: `declined`, `dropped`, `interrupted`, `capped`, `ended`, **and `session_ended`**. The sixth rides a `task_progress` rather than a `task_failed` and is NOT read by `calmTerminalStatus`, which is exactly why it is easy to leave out of a list and exactly why it is reserved on the same terms — it changes how the peer's card READS.
  - `taskId` stays caller-settable by design (validated, and silently dropped when it is not the poster's own exchange).
- **`authorKind` is CALLER-ASSERTABLE, not derived from the credential.** An explicit body value wins; `ctx.source` is the fallback. Load-bearing — the desktop posts agent results over the operator's cookie session. NOT assertable: `author_user_id` is always `ctx.userId`, and `system` is rejected by the route schema. **Treat `authorKind` as a display/routing claim scoped to one user, never as an authentication fact.**
- **DM auto-address is fail-quiet, never fail-closed.** A post into an `is_direct` channel with no caller `to` is stamped with the OTHER member, resolved live off `channel_members`. A roster that is not exactly two rows resolves to nothing and the post proceeds unaddressed rather than 400ing. Explicit `to` always wins. **Never auto-address in a non-direct channel.** **`intent === "chat"` skips peer resolution ENTIRELY** — not "resolves a peer and discards it": the fallback reads whatever `peerUserId` holds, so the only way a chat post can never be auto-addressed is for there to be nothing to fall back to. A chat post also therefore never inherits an open thread.
- **DM membership and visibility are IMMUTABLE** (`DirectChannelImmutableError` → 400) — that protects the `direct_key` identity and live peer resolution.
- **DELETES ARE PERMANENT — with one branch.** No trash, no restore, no retention window.
  - **A DM SOFT-deletes** — `deleted_at` on a direct channel is the CLOSE half of close/reopen; either side's next open revives the SAME row with full history. **A tombstoned DM is LIVE PRODUCT STATE. Never hard-delete one; never add `channels` to a tombstone-cleanup migration.**
    - ⚠ **ACCEPTED TRADE, ALREADY FILED — do not re-file it (F-189).** Since `20260810100000_channels_rls_hide_tombstoned.sql` added `AND deleted_at IS NULL` to `channels_member_select`, **closing a DM is no longer a LIVE event.** The close is an UPDATE, `realtime.apply_rls` evaluates the NEW record against that policy, the row is now invisible, and **the frame is dropped**. The peer's sidebar keeps rendering the closed DM until their next refetch (`listChannels` filters `deleted_at IS NULL`, so the next read is correct). **A downgrade from live to next-refetch, not stale-forever. Shipped knowingly; remedy sketched but NOT taken in F-189** — and the remedy's ORDER is the design (touch the peer's `channel_members` row BEFORE stamping the tombstone; after it, the same policy drops that frame too).
  - **Every OTHER channel HARD-deletes** (owner/workspace-admin only) as ONE statement — all six child FKs are `ON DELETE CASCADE`, so it is already atomic. **Do not add an RPC to "follow the pattern"**: the pattern is atomicity, and one statement has it.
  - **Three writers of `channels.deleted_at`:** the DM delete branch, `reviveChannel` clearing it, and `removeWorkspaceDepartedMember`. The third is server-to-server, takes no `ChannelContext` on purpose, and **must never be wired to a route or MCP op** — exposed it is an unauthenticated "evict this user from every room" primitive. **Order is crash-safety: close FIRST, delete the membership row SECOND.**
  - **`knowledge_entries.folder_id` is `ON DELETE SET NULL` — the trap.** Deleting a folder row alone ORPHANS its entries to the base root where they REAPPEAR. Delete the subtree's entries first.
  - **`ontology_memberships.parent_object_id`'s cascade is a LIE about the tree** — the column is on **`ontology_memberships`, NOT on `ontology_objects`** (`20260706120000_ontology.sql`, `REFERENCES ontology_objects(id) ON DELETE CASCADE`), so deleting an object cascades away the MEMBERSHIP rows that name it as parent and leaves every child OBJECT behind, parentless. `cascade_hard_delete_object` is the ONLY correct way to delete an object. **The wrong table name is the whole trap here** — looking for the cascade on `ontology_objects` finds nothing and reads as "there is no cascade".
  - **Deleting is a cache eviction, not just a write.** The query cache is IndexedDB-persisted (24h `gcTime`) and read hooks prefer `data` over `error`, so an INVALIDATED entry for a deleted row still RENDERS across relaunches. `removeQueries` the subtree; invalidating the parent list is not enough.
  - **`deleted_at` columns and their read-path `IS NULL` filters STAY.** A NEW read of such a table still carries the guard.
- **CLOSE IS PROPOSE-THEN-CONFIRM.** Closing settles the SHARED thread for BOTH members, so `closeTask` refuses an agent-token caller (403 `CHANNEL_CLOSE_IS_HUMAN_ONLY`) and the agent's terminal act is `op="propose_close"`, which writes NOTHING to the task row and posts a marked, non-terminal `task_progress`. **Closing over MCP is not possible at all.** Human closers: the web/SPA thread card and the desktop session window. The stale-threads cron proposes and never closes.
- **AN AGENT WRITES PROSE AND MILESTONES. NOTHING ELSE.** `task_started`/`task_finished`/`task_failed` state a fact about a RUNTIME and are refused from an agent-token caller at two layers (the MCP tool, fast and teaching; `service-writes-lifecycle.ts`, authoritative). **The seam is the CREDENTIAL — do not "simplify" it to a kind check**: the desktop's own echoes arrive on Supabase cookies and must keep working. `task_progress` stays agent-writable.
- **THE MILESTONE IS AN OP, NOT A KIND** — `op="milestone"` fixes `kind` at the routing seam, so "mark a milestone" and "send a reply" cannot be confused by picking wrongly between adjacent enum values.
- **Status is decided by FLAG, never by string.** Calm endings and `threadReopened` read as **strict `=== true`** on a reserved key. Matching body copy regresses the first time somebody improves the wording; a truthy coercion paints real failures calm.
- **Both status transitions ECHO, and `channel_tasks` stays OUT of the publication.** A status change reaches no peer surface by itself; the echo rings the `channel_messages` doorbell every peer already subscribes to. **Do not add the table — the doorbell is already paid for.**
- **FIRST CLOSE WINS, and the guard is in the STATEMENT** (`.eq("status", …)` inside the UPDATE; zero rows is the expected answer). **A second close is a 200 no-op naming the STORED outcome, not a 409.**
- **An echo failure degrades to `echoSeq: null` and NEVER throws** on close or reopen — the state change already committed, so throwing would report a change that happened as a failure. `null` is never a cursor.
- **The stale sweep's clock is `channel_messages`, never `channel_tasks.updated_at`** — that column's only writer is close/set_mode/reopen, so it equals `created_at` for every thread never closed.

Why/history: ENGINEERING.md §8 (Channels v1.1–v3.1, F-133, F-141…F-147, F-176).

## 6. Consent & trust

- **Consent is a server-side ROW, not an in-process promise**, so the gate survives the machine that raised it. The same request is answerable on **either** the web card or the desktop dialog — **first answer wins**.
- **Approve-in AND approve-out.** `inbound` = a teammate's agent addressed the operator; they must Allow/Deny **before** their machine spawns. `outbound` = the operator's own agent drafted a reply; a human must Send **before it leaves the machine**.
- 🔒 **A CONSENT READ IS SCOPED BY `(operator, workspace)`. OPERATOR ALONE IS NOT ENOUGH.** A row carries `operator_user_id` and nothing else identifying whose workspace raised it, so an operator-only filter returns rows from EVERY workspace they belong to. **Both columns, every read, no exceptions.** **RLS is not a backstop here**: the read runs as service role.
  - The type-level half is NARROWER than it sounds: `workspaceId` is a required field on `ConsentListOpts`, which is a **file-local, non-exported interface in `channels/server/repository-collab.ts`**. It binds callers of that one repository function — it is not a project-wide type that makes every consent read fail to compile. **The rule is the discipline; the type only fences the one door it sits on.**
- **Trust is evaluated SERVER-SIDE ONLY.** The desktop keeps NO local trust cache. Trust is re-checked against live workspace membership, never the rule alone.
- **TRUST IS RE-DERIVED AT EVERY CONSUME-TIME READ, not once at birth.** `channels/server/consent-service.ts › revalidateAutoAllow` re-runs the check on the way OUT of every path that can authorize, so revoking trust stops an already-created row; a row that fails is CAS'd to `expired`. **Old desktops fail closed with no client change** — the whole reason this lives on the server read path rather than in the client.
  - **A null `requester_user_id` fails closed** — nobody left to re-verify.
  - **`listConsentRequests` is DELIBERATELY UNSWEPT.** It is the audit surface and nothing authorizes from it; sweeping would rewrite settled history.
  - ⚠ **THE GUARD IS HTTP-LAYER ONLY.** Realtime and PostgREST hand out the RAW row. Both current consumers are invalidation-only by contract. **A future optimization that reads the subscription payload instead of refetching steps around it entirely. That is the thing not to do.**
- **Decisions are compare-and-swap on `status = 'pending'`.** Explicitly multi-writer: the pre-read is authorization-only, and a losing writer gets 409 re-read so the error names the status that won. **A human's Deny must never be clobbered by a late Allow.** The desktop treats its own 409 as settled, not a failure — no retry.
- **De-dupe key is `(operator, channel, kind, message_seq)` at ANY status**, deliberately: a denied trigger must never be re-raisable. `operator_user_id` is IN the key because every recipient of one message raises their OWN request.
  - ⚠ **The unique index is PARTIAL — `WHERE message_seq IS NOT NULL`** (`channel_consent_requests_trigger_key`, `20260726140000_channels_consent_hardening.sql`). **A row with a NULL `message_seq` is UNCONSTRAINED**: the database will happily store two, and the "denied cannot be re-raised" guarantee simply does not cover them. Deliberate — a request raised without a triggering seq has no trigger identity to de-dupe ON — but it means **any new consent path that can raise a seq-less request is raising one the DB will not protect.** Give it a seq, or de-dupe it yourself.
- **Human-only gates (`sessionOnly`):** `PATCH /consent/[id]`, `POST /trust`, `DELETE /trust`. The desktop passes a 90-day device token to every spawned agent, whose whole job is to process an untrusted teammate's message, and it has Bash — ungated it could read the token off disk and approve its own outbound review. `POST /trust` is worse than any single Allow (standing consent retires the gate permanently); `DELETE /trust` is gated for the mirror reason. **`GET` stays open on both.**
- **The operator is ALWAYS `ctx.userId`, never read from the body.** `requireOperatorRow` collapses missing / foreign-operator / cross-workspace into ONE 404 so ids cannot be probed.
- **Constants** (`features/channels/constants.ts`, verified 2026-08-11): `CONSENT_TTL_MS` = 24h, `PRESENCE_ONLINE_WINDOW_MS` = 90s, `UNRESOLVED_TOOL_PROFILE` = `"read_only"`. Expiry is lazy — no cron, no realtime event.
- **A null/unresolved tool profile falls back to `read_only`, matching the desktop.** Do not "fix" it to `full` because the column defaults to `full`: null means *this DTO does not know*, and "Full access" over a session the machine will run `read_only` is a lie in the direction that makes an operator relax.
- **Trust is WORKSPACE-WIDE** (`UNIQUE (operator_user_id, trusted_user_id, workspace_id)`, no channel column) and copy carries that scope.

Why/history: ENGINEERING.md §8 (v1.2, v1.4; F-174, F-188).

## 7. Realtime

- **The publication list is an INVARIANT, not a description.** A published table with no subscriber costs WAL decode plus a per-subscription RLS evaluation on every write, forever. A subscriber on an unpublished table is WORSE than an error — Realtime accepts the binding, reports SUBSCRIBED, and delivers nothing, so the surface silently stops updating.
- **17 tables, measured 2026-08-11** against `dopl-desktop-app/main/ui-sync.js › SYNC_TABLES`: `knowledge_bases`, `knowledge_folders`, `knowledge_entries`, `skills`, `skill_versions`, `ontology_clusters`, `ontology_objects`, `ontology_memberships`, `ontology_relationships`, `chats`, `chat_messages`, `chat_folders`, `channel_consent_requests`, `channels`, `channel_members`, `channel_messages`, `agent_presence`. **The DB side is deploy state — verify with `supabase db reset` or `grep -rn "ALTER PUBLICATION" supabase/migrations/`.**
- **`test/ui-sync-tables.test.mjs` pins BOTH directions** against `supabase/migrations` and `SYNC_TABLES`. **Publication changes and subscriber changes MUST ship in the same release.**
- **AN EVENT IS A DOORBELL, NEVER CONTENT.** Subscribers trigger a filtered service refetch — never payload merging — so RLS and service filters stay authoritative. `ui-sync.js` states this in its own trust-model header.
- **REPLICA IDENTITY is the second half of the publication invariant, and it is what makes DELETEs deliverable at all.** Both subscribers bind `filter: workspace_id=eq.<id>`; on DELETE the deployed `realtime.apply_rls` tests that filter against `old_columns`, which is *the replica identity* — so under `REPLICA IDENTITY DEFAULT` (primary key only) `workspace_id` is absent, the filter can never match, and **the frame is silently dropped.**
  - Fix is `REPLICA IDENTITY USING INDEX` on a unique `(workspace_id, id)` — **not FULL**: FULL logs the entire old row on every UPDATE and would detoast large bodies on every autosave.
  - `ui-sync-replica-identity.test.mjs` pins the INVARIANT (identity must contain `workspace_id`), not the mechanism.
  - **`old_record` is separately redacted to the primary key on any RLS-enabled table**, so a DELETE frame arrives bare even now — the doorbell pattern is not optional, there is no payload to merge.
  - Some tables stay DEFAULT on purpose, and `ui-sync-replica-identity.test.mjs › NO_DELETE_DOORBELL` **states a reason per table rather than merely listing them** — cascade-only children (`chat_messages`, `channel_messages`), never-deleted rows (`agent_presence`), and `skill_versions`, whose retention trim is the highest-frequency delete in the schema.
  - ⚠ **`channels` is on that list, but NOT for the reason it used to be.** "It still soft-deletes" was retired 2026-08-08 (C-16 / F-173) — **a non-DM channel HARD-deletes now**. The exemption survives on a different reason, and the difference matters: **`channels`' OWN DELETE frames ARE dropped** (it is `REPLICA IDENTITY DEFAULT`, so the WAL record is the primary key alone and both subscribers' `workspace_id=eq.<id>` filter can never match) — **the doorbell that actually rings is the CASCADE**. The hard delete cascades real DELETEs onto `channel_members`, which DOES carry `workspace_id` in its replica identity (`20260807150000`) and rides the same refetch signal in both subscribers. Adding an identity to `channels` would widen `touchChannel` — one UPDATE per message posted — to buy a frame that already arrives. A DM delete is still an UPDATE, and §5 records what that costs (F-189).
- ⚠ **Do NOT verify replica-identity behaviour against upstream `walrus`** — its master returns `coalesce(..., true)` here and says the opposite of what is deployed.
- **A tombstone-by-UPDATE on a published table whose SELECT policy hides tombstones has silently traded its delete doorbell for a refetch** — `apply_rls` evaluates the NEW record, finds it invisible, drops the frame. **If you add `deleted_at IS NULL` to a published table's policy, you are making that trade. Decide it, do not inherit it.** The remedy shape is to touch a SIBLING published row that stays visible BEFORE stamping the tombstone.
- **Never construct a raw `supabase.channel()` for `postgres_changes` in feature code.** Go through `useWorkspaceTablesRealtime`; all mounts sharing a `(topicPrefix, workspaceId, tables)` key ride ONE ref-counted channel via `shared/realtime/shared-channel-registry.ts`, which owns reconnect backoff, a StrictMode-proof teardown grace window, and **generation-unique topic names** (realtime-js dedupes by name and forgets removed channels only after the leave push settles, so topic reuse resurrects corpse channels).
- **Any new live surface MUST use `shared/realtime/refetch-coordinator.ts`** or it will clobber in-flight typing.

Why/history: ENGINEERING.md §7 (Realtime & new-workspace seeding).

## 8. Write layer — client mutations

Three files: `shared/api/query-keys.ts`, `shared/hooks/use-api-mutation.ts`, `shared/ui/pending.ts`.

- **Never retype a key array at a call site.** `apiQueryKey(path, {workspaceId, query})` is the exact tuple the read hook registers; `apiPathKey(path)` is the one-element PREFIX; `apiResource(path)` hands back both. **Writes patch by the prefix**, because TanStack matches per array ELEMENT and a writer does not know which query-param variants a reader mounted. **A key that differs by one element is a silent no-op** — the write lands in an entry no observer is subscribed to; nothing renders, nothing fails.
- **Patches operate on the RAW response body** — the read hook stores what the endpoint returned and applies `select` on read.

**The eight rules, none negotiable:**

1. **Invalidation is EXPLICIT.** Auto-invalidating every patched key re-downloads the cache the mutation just reconciled. List only the caches this write could NOT compute — ordering, `lastMessageAt`, a server-written lifecycle echo.
   **The ONE exception is the COLD CACHE.** `optimistic` and `reconcile` both decline on an entry with no data, so on a cold start the write lands server-side and never reaches the screen, invisibly. A write whose reconcile is its only path to the screen names its keys through **`coldKeys(client, keys)` — exported from `use-api-mutation.ts`, ONE implementation; the old feature-local copies are deleted.** It runs in `onSettled` (after `reconcile`), so "still empty" is the decline itself; warm caches re-download nothing.
   **Rule 4 is not a substitute.** Whether a write names its keys conditionally is decided by whether its OWN response can reconcile the surface — never by symmetry with the write next to it.
   **A per-item key cannot be reached by a prefix**: a write changing what a server-resolved per-item pane says must NAME each id, captured at submit.
2. **Cancel BEFORE patching, and only queries that HAVE data.** Cancelling second restores the very data the write just replaced; cancelling a first-load query strands the surface empty with nothing scheduled to fill it.
3. **`settleWith` + `useRefetchGate`, never a hand-rolled busy counter.** The gate owns the in-flight count and releases the deferred refetch in `onSettled`, so a write that THROWS cannot strand it.
4. **Key every optimistic write by the id captured AT SUBMIT.** Per-channel reads use `keepPreviousData`, so a switch renders the previous channel's data. **AND a read that FEEDS a write's payload must expose `isPlaceholderData`** — capturing the id protects the KEY and does nothing for a field the draft derives from placeholder data. The gate belongs in the pure decision layer, so it disables Send and says why rather than no-opping.
5. **MERGE, NEVER REPLACE, when the response is narrower than the cache.** Assigning the server's row over the cached one silently drops every field the write endpoint does not return. **A `reconcile` is not automatically safe just because the server answered — the question is always what it answered WITH.**
6. **A feature's READS must be on `useApiQuery` before its WRITES adopt this layer.** There is nothing to patch otherwise, and the failure is silent: the surface keeps rendering from whatever `useState` copy it held. Converting writes first produces a feature that looks converted and behaves exactly as before.
7. **`CREATE_RESOLVE` is the pattern for a server-minted id with instant render** — render a provisional row under a client-side id, resolve it when the response lands. **Ontology uses a reducer for this deliberately** (`graphReducer`, pinned by `features/ontology/graph-state.test.ts`): the board renders from a reducer, not a cache, so there is no entry to patch. **While a row is provisional it is PENDING for real** — its id is not addressable and the realtime write gate is held.
8. **`pendingRow` on a CONTROL closes toggle races.** On a row it is cosmetic; on a toggle, segmented control or role select it is the thing that stops the second click and the two conflicting PATCHes.

- **Idempotency is the client's job — WHERE IT IS DONE AT ALL, WHICH IS ONE HOOK.** A minted `client_msg_id` makes a retry after a rolled-back failure return the FIRST attempt's stored row instead of double-posting. ⚠ **Measured 2026-08-11: NINE feature hook files register optimistic writes and exactly ONE mints the key** — `channels/hooks/use-thread-writes.ts`. The other eight (`members/hooks/use-team-writes.ts`, `use-access-writes.ts`, `use-join-requests.ts`, `use-member-writes.ts`, `use-invitation-writes.ts`, `chats/hooks/use-chat-writes.ts`, `channels/hooks/use-channel-preference-writes.ts`, `channels/hooks/use-channel-lifecycle-writes.ts`) carry **no idempotency key at all**. **Do not read this bullet as coverage.** Most of those are PATCH-shaped and idempotent by nature, which is why the gap has been survivable — but it is a gap, not a design. **Extending the key beyond thread writes is OPEN and UNFILED** (the `client_msg_id` entries in the findings log are about SERVER-side `create_thread` dedup, a different problem). Whoever needs it should file it before building it.
- **An unspecified query option must be OMITTED, never passed as `undefined`.** TanStack merges by spread, so a key present with `undefined` DELETES the client default underneath it instead of falling back to it. Route caller-supplied options through `definedOnly()`. **`0` is not "unset"** — test `!== undefined`, never truthiness.
- **Known gap:** the layer cannot express a PREDICATE invalidation — `invalidate` returns KEYS, while TanStack's `invalidateQueries` accepts a `predicate` this layer cannot pass.

Why/history: ENGINEERING.md §7 (Writes: `useApiMutation`).

## 9. Read projections

⚠ **THIS SECTION IS A DISCIPLINE, NOT A DESCRIPTION OF THE TREE.** It was established in ontology and chats and is enforced by review, not by a lint or a test. **Known non-conformers exist and are named below.** Read the rules as "what a NEW read must do", never as "what every read already does" — the second reading is what makes an agent trust a `select("*")` it finds.

- **A whole-workspace list read selects COLUMNS — never `*`, never the JSONB.** Heavy fields belong to the DETAIL path, which returns ONE row in full. `features/ontology/server/dto.ts` holds both sets side by side (`ONTOLOGY_OBJECT_COLS` vs `ONTOLOGY_OBJECT_SUMMARY_COLS`) so the difference is legible where it is chosen.
  - **Known `select("*")` non-conformers, measured 2026-08-11:** `channels/server/repository.ts › listChannels` and `› listMyMemberships`, `channels/server/repository-collab.ts › listTrustRules` and `› listConsentRequests`. Bounded in practice by roster and rule counts, not by design.
- **Two views of one resource is a query PARAMETER, not a second route** (`?view=full|summary`). A second endpoint gives one resource two auth wrappers, two error mappings and two futures. **The expensive view is the DEFAULT** — nothing may get a thinner answer than it asked for — and an unrecognised `view` is a 400, never a silent fall-through.
- **The summary is a DISTINCT TYPE, not the full type with empty arrays.** `attributes: []` asserts the object has none; omitting the field says this view did not ask.
- **A SHARED HELPER IS TYPED BY WHAT IT READS, NOT BY WHO CALLS IT.** A helper whose parameter says `OntologySnapshot` forces every caller to fetch the JSONB *for the argument to typecheck* — the type, not the code, keeps the cheap read out. Widen to the minimum structural shape it actually touches. **When the helper's RETURN carries the element through, make it GENERIC, never widened** — widening strips the heavy fields off the DETAIL path's type. No unions, no `any`.
- **Every whole-workspace list read carries a `limit`, and a clipped read SAYS SO** — **the rule for a new read; NOT a description of the current tree.** The same four reads above carry no `limit`, and neither does `knowledge/server/repository-folders.ts › listFoldersForBase` (which does select columns, so it fails only this half). A read returning AT its ceiling counts as clipped (at is indistinguishable from over). **A cap that renders identically to an exhausted list is the bug, not the fix.** One wording, one module (`packages/mcp-server/src/tools/ontology-clipped.ts › clippedNote`), emitted beside the section it clipped, never in a footer a skimmer drops.
  - The notice may NOT promise another read as the remedy (the detail path carries identical ceilings and reports nothing), and may NOT let a clip pass as an absence — a miss, "no matches" and "the graph is empty" are assertions a clipped read never established.
  - **A clip is not a per-op CAP** — the cap hid matches we found, the clip hid rows we never scanned. Report separately; never offer "narrow the query" for a clip.
- **Narrow reads live in `repository-projections.ts`**, beside `repository.ts`, same rules. ⚠ **Exactly ONE such file exists — `src/features/ontology/server/repository-projections.ts`.** It is a PATTERN to follow when a second feature needs one, not a convention other features already observe; do not go looking for `channels/server/repository-projections.ts`. Each exists because its wide sibling let the cost of a read be set by the size of the workspace instead of the size of the answer.
- **Prefer FOLDING a second read into the first over minting a new endpoint** whenever the second read is strictly downstream of the first.

Why/history: ENGINEERING.md §8 (Read projections, F-157/F-165).

A plain `z.object` DROPS unknown keys, so a mistyped addressing argument is accepted, never reaches the handler, and the result narrates success over an invisible delivery failure. **`tool()` is the regression to watch for** — the positional overload cannot carry a built schema. **FIVE `McpServer` test mocks exist; FOUR expose `registerTool` and deliberately NOT `tool`** (`server.test.ts`, `retirement.test.ts`, `factory.test.ts`, `tools/narration.test.ts`), so a revert is a TypeError in each. ⚠ **The fifth is the INVERSE and is not a hole: `tools/channel-discovery.test.ts` stubs `McpServer` as `class { tool() {} }`** — it constructs no server and registers nothing; the stub exists only to satisfy the SDK import that `buildInstructions` drags in. **Do not "fix" it to match the other four, and do not count it as a fifth guard.** (`meta-gate.test.ts` uses the REAL SDK `McpServer`, not a mock.) The behaviour itself is pinned through the real SDK over `InMemoryTransport` in `packages/mcp-server/src/strict-args.test.ts`.
- **UNTRUSTED FRAMING — a tool result has a VALUE zone and a BODY zone.**
  - A **VALUE** is a name, title, slug, label, path, snippet or error echo spliced into a line WE wrote. **Every member-typed string spliced there goes through the ONE neutralizer: `packages/mcp-server/src/tools/narration.ts › neutralizeInline` / `inlineOr` (`INLINE_TEXT_MAX` = 160).   - A **BODY** is content rendered as itself under framing that says what it is. **NOT neutralized** — clipping would delete the feature. Where a body has no framing and no indent it is INDENTED instead, removing its ability to begin a line.
  - **Everything outside a body — headings, bullet heads, author labels, legends, confirmations, error lines — is read by the model as NARRATION BY THE SERVER.**
  - **A scoped header is emitted FIRST, above the content it frames** (a caveat under the content is read after the injected line it warns about).
  - **A header is emitted only where the content can be ANOTHER MEMBER'S** — a header on every result trains agents to skip headers. Chats gate on visibility; KB and skill gate on AUTHORSHIP via the one predicate `narration.ts › isForeignAuthored`, which reads **BOTH author columns** (a row you created and a peer last EDITED carries the peer's words) and **fails CLOSED**.

  - **Never a member-typed name without an immutable id beside it.**

The reason is enumeration, not secrecy — an agent can walk every public channel and `op="members"` each one. `isAdmin` is threaded from the boot ping and **DEFAULTS FALSE at every hop** — fail-closed by default VALUE, the only way a defaulted boolean is safe. ⚠ **The MCP surface is deliberately TIGHTER than web. Do not "restore parity" by loosening MCP** — close the gap by applying the same admin-or-self scrub to the web `/members` DTO.

Absent/blank/near-miss → no key at all, read as external. **Nothing may grant access on either.**

## 11. Desktop session rules

- **Containment is FOUR LAYERS, applied together** — `--tools` (a POSITIVE bound over built-ins; does NOT bound MCP tools), `--settings` (whose `permissions.deny` outranks every allow), `--disallowedTools` (the same names at the CLI layer, because in `-p` mode an invalid settings file is SILENTLY ignored), and `--strict-mcp-config`. **`--allowedTools` is ADDITIVE — it pre-approves, it does NOT bound**; the operator's global settings keep applying.
- **MCP allow/deny entries are EXACT-MATCH, not string-prefix.** The bare server prefix is valid ONLY in a deny list.
- **Profile tables** (`main/tool-profiles.js`, verified 2026-08-11): `READ_BUILTINS` = `Read, Grep, Glob, LS, TodoWrite`; `DOPL_SAFE_TOOLS` = **9**; `DOPL_ADMIN_TOOLS` = **4**; `RETIRED_DOPL_TOOLS` = **4**; **`UNIVERSAL_HARD_DENY` = admins + retired = 8 names.**
- **`full` MEANS FULL — and the two spawn lanes are IDENTICAL ONLY IN THE HARD-DENY SET.** `main/session-profiles.js › SESSION_HARD_DENY` **is** `UNIVERSAL_HARD_DENY.slice()` — not a copy, not a superset — so under `full` both lanes hard-deny exactly those eight names and **everything else is live-gated** by the operator's permission preset. ⚠ **THAT IS WHERE THE SAMENESS STOPS. `tool-profiles.js`'s own header says "the two lanes answer `full` identically"; it is describing the DENY FLOOR, and reading it as the whole spawn shape is the mistake this bullet exists to stop** (the first draft of this file made exactly that copy). **This is a containment claim — verify it per lane before relying on it.** Measured 2026-08-11:

  | Under `full` | **Headless CLI lane** (`session-spawner.js` → `tool-profiles.js › buildRestrictionArgs`) | **SDK lane** (`session-query.js › buildSdkOptions`) |
  |---|---|---|
  | Hard deny | `--disallowedTools UNIVERSAL_HARD_DENY` (8) | `SESSION_HARD_DENY` (same 8) **+ `buildSecretPathDenyRules()`** |
  | Positive bound on built-ins | none (no `--tools`) | none (`builtinTools: []`, so `options.tools` is never set) |
  | Pre-approval | none (no `--allowedTools`) | **`allowedTools: READ_BUILTINS`** |
  | Operator's global settings | **APPLY** (no `--settings`) | **NEVER** — `settingSources: []`, unconditionally, on every profile |
  | Operator's global MCP servers | **LOAD** (no `--strict-mcp-config`) | **DO NOT LOAD** — `mcpServers` is `buildMcpServers(…)`, the single `dopl` HTTP entry, and nothing else |

  **So "`full` grants the operator's REAL tools, global MCP servers included — nothing narrows it" is TRUE OF THE CLI LANE ONLY.** On that lane `buildRestrictionArgs` returns exactly one flag and that is deliberate — **do not add `--tools`, `--allowedTools`, `--settings` or `--strict-mcp-config` there.** The SDK lane is narrowed by construction and always has been: `settingSources: []` and a single-entry `mcpServers` are load-bearing (`// ALWAYS — the global allow-list can never shadow a gate`), and **removing either to "restore parity" would hand a channel session the operator's whole global config.** The SDK lane is also where `permissionMode: 'default'` is pinned, so `canUseTool` cannot be short-circuited.
  - **`AUTO_TOOLS`/`BYPASS_TOOLS` are POSITIVE allow-lists** — an unclassified name gates in every mode, `bypass` included. ⚠ **SCOPE: "no released built-in is on either or in `preApproved`" is true ONLY of the built-ins F-177 RELEASED** (`Task`, `Agent`, `Artifact`, `SendMessage`, `Cron*`, `Skill`, `ToolSearch`, `EnterWorktree`, …), which is the claim `tool-profiles.js` actually makes. **Read as a universal it is plainly false:** `AUTO_TOOLS` = `READ_BUILTINS` + `EDIT_TOOLS` + `MultiEdit` + `DOPL_READ_TOOLS`, `BYPASS_TOOLS` adds `ESCALATION_TOOLS` (`Bash`, `BashOutput`, `KillShell`, `WebFetch`, `WebSearch`) + `DOPL_WRITE_TOOLS` + `BYPASS_READS`, and `preApproved` is `READ_BUILTINS` on **every** profile. **Do not "finish the job" by pre-approving any of the released set** — a shadowed tool never reaches `canUseTool` at all.
  - **`read_only` and `dopl_only` did NOT change** — they still hard-deny the whole of `DENIED_BUILTINS` plus admins and retired tools.
  - **Dropping a name from a deny list makes it UNCLASSIFIED, which resolves to `gate`** — one click from running. Containment must not depend on the server's current tool list.
- **`main/sdk-loader.js`'s dopl MCP entry carries `alwaysLoad: true`. Do not remove it** — pinned by `test/prompt-profile-drift.test.mjs`. Every MCP tool is deferred behind `ToolSearch` once tool search is on (it defaults on), so without `alwaysLoad` the session's own delivery path sits behind a call the prompt forbids by name.
- **The per-server `tools` policy is NEVER SENT.** `doplToolsPolicy` stays in `buildMcpServers`' signature and the profile table as **a record of intent that is deletion-only, never a live input.** The CLI validates `--mcp-config` PER ENTRY and a failed parse **DROPS THE WHOLE SERVER ENTRY** rather than stripping the field; `disallowedTools` already carries the identical bound. **The reusable lesson: a config field is not verified by testing the function that computes it — assert the object that crosses the process boundary, or read back what the runtime says it loaded.**
- **AN UNKNOWN TOOL PROFILE FAILS CLOSED AND SAYS SO.** `normalizeProfile` resolves anything unrecognized to `read_only` through an injected sink. **An explicit `'full'` is untouched.**
- **`mcp__<server>__` IS THE CLIENT'S PREFIX, NEVER OURS TO ASSUME.** Other clients use different segments, so **every tool name reaching the gate is normalized ONCE at the top of `grantDecision`** (`main/mcp-tool-names.js`) and hard-deny, pre-approval and both lookups use that one value. **Never add a fourth matcher comparing a raw name against an `mcp__dopl__…` literal** — its worst face is the deny direction. **The GRANT KEY is the deliberate exception and stays on the RAW name**: a grant is scoped to the shape the operator was shown.
- **AXIS B governs the own channel in BOTH directions.** An own-channel POST follows the outbound half; own-channel READ-ONLY ops follow the INBOUND half, because a read brings the peer's words into this agent's context. **The set is FIVE ops — believe the constant:** `main/session-profiles.js › OWN_CHANNEL_READ_OPS = ['read','await','list_threads','get_thread','members']` (verified 2026-08-11). Everything else gates in every posture, including any post or read naming another channel (**a slug counts as another channel — the safe failure**) and `read_sessions`, whose `channel` is an optional filter.
- **A POSTURE THE OPERATOR SET LIVES AS LONG AS THE SESSION DOES**, standing grants included — they survive an idle park and resume. The threat is answered elsewhere: an abandoned session ENDS (terminal, strictly stronger than a downgrade), and **the real boundary was always the PROFILE**, checked FIRST and unwidenable by any posture, grant, or `bypass`. **THE ONE PARK THAT STILL RESETS IS THE AUTH HOLD.**
- **A stored permission posture may only apply to a launch a human is approving in that moment.** It is an ARM, not a setting (`main/channel-prefs.js`), enforced three ways: **single use**, **expiring** (a record with no timestamp is EXPIRED, so an upgrade can only narrow), **one consumer** (the inbound-approved path, only on a real human allow). A human `allowed` is distinguished from a standing `auto_allowed`, and that verdict is a **call argument, never stamped on the persisted record** — an authority verdict must not survive a restart and re-authorize a launch from disk. **A parked shell refuses a posture even if one is handed in. Never present the arm as a stored preference** — the heading is *"For the next request you allow"*, never *"this channel"*.
- **One channel's arm has ONE value across every mounted reader.** Per-component snapshots let two surfaces revert each other.
- **THREE TIMER BOUNDS, ONE HANDLE, ONE ARMING PATH.** `main/session-state.js › idleTimeout` is the only place the decision is made (verified 2026-08-11): `DEFAULT_IDLE_MS` 15 min → park; `AWAITING_PEER_IDLE_MS` 4 h → still a park (suppressing the timer leaves a live query alive forever when the reply never comes); `ABANDONED_MS` 12 h → END; `LAUNCHING_MS` 5 min → a launch that never emits `system/init` ends itself. **Adding a second timer here is the regression** — one handle is what makes every teardown path correct.
- **`MAX_CONCURRENT_SESSIONS = 4`** (`main/session-pool.js`). A COST ceiling, not just a concurrency one: every per-session bound is MULTIPLICATIVE against it. **Release is hand-placed at every settle point, NOT a `finally` — if you add a return path, you add a release.**
- **THE PERSISTED CURSOR MOVES ONLY PAST A MESSAGE WHOSE DISPATCH LANDED.** The per-page loop lives beside the dispatch it gates; `dispatchMessage` returns a **deferral REASON, falsy = handled**. A held cursor is bounded (8 attempts ≈ 4 min) then a LOUD escape — retrying forever trades a bounded announced loss for an unbounded silent stall of every later message.
- **QUIT DOES NOT ORPHAN `claude` CHILDREN.** `main/quit-guard.js` NAMES the threads a quit would interrupt (title + channel, never a count), ends each through the calm `inactive` terminal so the peer is told, and RACES one final state-push flush against `FLUSH_DEADLINE_MS` (1500 ms, verified 2026-08-11) rather than awaiting a 15s HTTP budget. **The kill predicate is "holds a live child" (`!settled && !parked`), NOT the pill state** — a session between turns reads `idle` and still owns a process. **Every path fails OPEN.**
- **All THREE auth legs arm `beginPendingAuth({ requireState: true })`** — browser OAuth (`main/auth-actions.js`), in-process password adoption and the magic link (`main/auth-password.js`). **The gate fails closed in BOTH directions:** a fragment echoing a state may spend ONLY the record carrying that exact nonce (a mismatch matches nothing and does NOT fall back to presence+TTL), and a state-less fragment may spend only a record that does not require one — of which nothing writes any more.
- ⚠ **SHIP-ORDER GATE, one-way: the state-echoing WEB deploy must be LIVE before the new desktop build ships.** Never the reverse, never the same window without confirming the web half landed first.
- **"Signed in" = the encrypted blob OR a fresh cookie identity.** `isSignedIn()` stays SYNC; `ensureSignedIn()` is the ASYNC gate for the two boot callers that can await.
- **The cookie jar is HOST-locked, not origin-locked** — a cookie must be HOST-ONLY for the app origin (leading dot stripped, then `===`), and in-window navigation is locked to the exact origin.
- **Identity is CROSS-CHECKED; a conflicted machine adopts nothing.** Resolution is an explicit sign-out.
- **`signOut()` tears down FOUR credentials** — the Supabase blob, the cookie jar, the MCP device token (server-side revoke FIRST, while the cookie jar it authenticates on still exists), and the Claude inference token. **Clearing the inference token does NOT revoke it at Anthropic**, and the log says so.
- **ONE 401 REPAIR, SHARED (`main/api-repair.js`).** Force ONE rotation through the shared single-flight, write the cookies so the retry carries a DIFFERENT credential, retry EXACTLY once, and let a 401 that survives a fresh token SURFACE. **Exactly two cookie-attaching seams; a third copy of the rule is the bug** — pinned by a test that ENUMERATES the seams rather than trusting a memory of them.
- **`null` means "COULD NOT ASK"; `[]` means "there are none".** Never collapse them. **UNKNOWN is not EMPTY.**
- **`claudeAvailable()` and `sessionSpawnAvailable()` are NOT the same question.** The first asks "is there an EXTERNAL `claude` on PATH" (what `claude mcp …` needs); the second asks "can a session RUN at all" (bundled SDK first, external CLI second). **Anything gating a channel TRIGGER or a session launch asks the second.** Do not collapse the names.
- **A CONTAINED SESSION'S PROMPT MAY NOT ORDER A DENIED TOOL** — an ordered call the operator must clear before the agent does anything is no better than a denied one.
- **ZERO PEER BYTES IN AN ATTENDED-HANDOFF PREFILL.** That session is the operator's personal Claude with no containment, so the template interpolates narrowed IDs and nothing else — no names, no titles, no bodies. **Treat any new field there as the security boundary it is.**
- **A deep link returns a ROUTE, never a URL.** Every value is assembled from segments decoded and character-checked one at a time. **`new URL` DOES run first — for the ORIGIN check — but the segment walk is over the RAW path string, never `parsed.pathname`**, because `new URL` NORMALIZES `..` away rather than refusing it (`/{seg}/../../etc` arrives as `/etc`, a link that says one thing and resolves to another). `main/deep-link-target.js › rawPathOf` cuts the path out of the string (query and fragment come off FIRST), and `pathSegments` percent-**decodes each segment and THEN** rejects `.` / `..` — decoding first is what stops `%2e%2e`. **Handing that walk a pre-normalized path silently disarms it, because by then there is nothing left to refuse** — which is how the bug was found: the unit case passed, since it was handed the raw string. **Malformed opens home; unknown resolves as deep as it can — there is no failure mode where a Dopl link does nothing.**
- **`WORKSPACE_PAGES` in `main/deep-link-target.js` is a HAND COPY** of the SPA routes (main cannot import TypeScript); `test/deep-link-target.test.mjs` re-reads `routes.tsx` and fails on drift. **`main/agent-names.js` is likewise a byte-for-byte PORT** of the web module, held by a parity test — **change the TS module FIRST, then the port.**
- **Preload surfaces are a PINNED INVENTORY — `test/preload-parity.test.mjs` fails on ADD as well as on REMOVE.** ⚠ **The old rule ("every callable op the remote preload exposes must also exist in the SPA preload") is RETIRED: the remote shell is deleted and its preload orphaned**, so there is no second preload left to compare against and no reference implementation. What replaced it is an explicit list of ops, asserted against preloads that are **EXECUTED against a fake `electron`** (the surface the shell really exposes, not a grep over source text). A derivation from the tree was tried and rejected on measurement — it found 3 of ~20 ops, because the tree destructures the bridge or reaches it through typed wrappers. **ADDING an op fails this test on purpose**: the pin is worth only what its last review was, so a new op gets looked at rather than absorbed. The reason any of this exists is unchanged — the shared `src/` tree feature-detects each capability and renders **nothing** when absent, so a gap does not fail, **it deletes a feature silently.** **Adding an op is still a FOUR-file change** (the preload, the `ipcMain` handler, the renderer-side typed mirror, the web tree's feature detector) — **plus the pin.**
- **Every renderer-reachable `ipcMain.handle` is sender-bound** via `mainOnly()`, which checks the sender IS the main window's `webContents` **and** that it is that window's TOP frame — a cross-origin iframe SHARES its host's `webContents`, so identity alone is not enough. Fails closed; the refusal shape matches an invalid-payload rejection so a hostile page cannot probe the difference.
- **The version floor FAILS OPEN.** Offline, timeout, 5xx, captive-portal HTML, a malformed floor, an unparseable own version — all "no floor", app opens. **No floor is ever cached to disk.** Two anti-brick guards from two sources of truth: the server refuses a floor above the declared latest; the client degrades when no updater exists or when a COMPLETED check found nothing newer (a FAILED check never sets that evidence).
- **`GET /api/version` is unauthenticated, and that takes TWO places** — `PUBLIC_ROUTES` **and** `SELF_AUTH_ROUTES` in `src/proxy.ts`, because the proxy 401s every unmatched `/api/**` before a route runs. Pinned by `proxy.test.ts`.
- **Never log token values.** Every silent decision is one line to `userData/listener.log` via `diag()`.

## 13. Release pipeline

- **`npm run release` in `dopl-desktop-app/` is a WRAPPER SCRIPT, not `electron-builder --publish always`.** It is `bash scripts/release.sh` (verified 2026-08-11). ⚠ ENGINEERING.md §18's "Commands" block still documents the raw invocation — **the script is the supported way to ship.**
  - **The POST-UPLOAD ASSERTION IS THE ENTIRE POINT.** `electron-builder --publish always` reports success on a partial upload; two consecutive releases each lost a DIFFERENT artifact silently. The script re-reads what GitHub actually has and refuses to call it a release until every expected name is there and the public feed URL serves the same bytes as `dist/`.
  - It re-hashes after stapling: the afterSign hook staples the `.app`, THEN `latest-mac.yml` is generated, and only THEN is the DMG stapled — which changes the DMG's bytes.
  - Flags: `--dry-run` (build + staple + re-hash, publish nothing), `--skip-build` (resume from an existing `dist/` — the repair path both real incidents needed). **No secret is ever echoed** — credentials are probed for PRESENCE only.
- **The GitHub release TAG must be `v<version>`** or electron-updater will not match the feed.
- **`renderer/app/` must exist before a release** — build output of `apps/desktop-ui` (`npm run build:ui` at the repo root), gitignored.
- **The auto-updater never force-restarts.** It installs on normal quit or an explicit tray action — a background listener must not yank an active spawned session.
- **The download URL is RESOLVED, never guessed.** electron-builder stamps the version into the artifact name, so `/releases/latest/download/:asset` is evergreen in the RELEASE, not in the asset NAME; `GET /download` reads the dmg's name out of `latest-mac.yml`. **Every failure still lands on a github.com URL** — a Download button may not show anybody a stack trace.
- **`latest` is DERIVED, not declared** (`shared/version/latest-release.ts` reads the electron-updater channel file — a release ASSET, outside the `api.github.com` 60/hr-per-IP quota, and the same fact the client reads). **Nothing is bumped by hand at release time.**
- **The floor rides CODE with an env override read per request** (`shared/version/desktop-floor.ts`). `DEFAULT_MIN_VERSION` and `DEFAULT_DECLARED_LATEST` are bumped in the same release commit, and a same-commit test pins floor ≤ latest so the clamp can never refuse its own release. **Malformed = no floor**, the fail-open direction. **Do not set `DOPL_DESKTOP_LATEST_VERSION` from `dopl-desktop-app/package.json`** — that file is a claim about what should ship and runs AHEAD of what is published; a latest ahead of reality permits a floor nothing can install.
- **THE SHIP-ORDER GATE IS WEB-BEFORE-DESKTOP.** Any desktop build requiring a server behaviour ships only after the web deploy carrying it is LIVE. The `requireState` auth gate (§11) is the worked example; the notify-scope column drop is the pattern: code deploy → raise the desktop floor → then the destructive migration.
- **Deployed values are measurements.** Whether `CRON_SECRET` is set, which migrations are applied, what `DOPL_DESKTOP_MIN_VERSION` holds — **verify by observing the deployment**, e.g. `curl -s -o /dev/null -w '%{http_code}' https://www.usedopl.com/api/cron/stale-threads` (401 = gated and live, 503 = secret unset; the apex 307-redirects to `www`, so check without `-L` or you learn nothing). Never record the answer here.
- **Three crons, wired in `vercel.json`, gated by `requireCronSecret`** (verified 2026-08-11): `oauth-cleanup`, `reconcile-seats`, `stale-threads`.

## 14. Testing gates

**Definition of green** — five suites, two lints, TWO typechecks, and four more gates that are easy to forget because they are not test suites:

| Command | Scope |
|---|---|
| `npm test` (root) | `vitest run` over `src/` |
| `npm test -w @dopl/client` | `packages/dopl-client` |
| `npm test -w @dopl/mcp-server` | `packages/mcp-server` (incl. MCP parity) |
| `npm test -w @dopl/desktop-ui` | `apps/desktop-ui` |
| `cd dopl-desktop-app && npm test` | `node --test 'test/**/*.mjs'` |
| `npx eslint` (root) | the root tree |
| `cd dopl-desktop-app && npm run lint` | the desktop tree — its OWN config, where the 500-cap and `no-redeclare` live |
| `npm run typecheck` | `tsc --noEmit` — **`src/` + `scripts/` + the Next tree ONLY.** Root `tsconfig.json` EXCLUDES `apps` and `packages` |
| **`npm run typecheck -w @dopl/desktop-ui`** | the SPA — **outside the root program**, and `npm test -w @dopl/desktop-ui` (vitest) does not typecheck. Also the only compile-time cover the unrouted retirement leftovers have |
| **`node scripts/check-doc-refs.mjs`** | doc anchors: files exist, `F-NNN` resolve, `path › symbol` anchors resolve. **NOT covered by `npm run lint`** — `globalIgnores` excludes `scripts/**` |
| **the `size-check` job** | the 500-line cap, **over `packages/` only** — an inline `find`/`awk` in ci.yml, not a script and not eslint |
| **`npx tsx scripts/check-knowledge-type-drift.ts`** | knowledge types, server vs SDK |

`npm run test:all` chains the first four **and nothing else** — it is not the definition of green. **CI is `.github/workflows/ci.yml`**, five jobs (`build-test` on ubuntu+windows, `desktop`, `typecheck-lint`, `size-check`, `type-drift`), and runs every row above — **path filters are DELETED on purpose**, because a filter over a repo-wide job would let a `src/` PR skip the `src/` suite.

- **Both trees measure a TRUE ZERO on lint — 0 errors, 0 warnings, both exiting 0 (measured 2026-08-11).** So the next warning to appear is a NEW one. ⚠ **But CI does NOT enforce that, and the two facts must not be collapsed.** `--max-warnings` is **deliberately unset** on both lint steps, so **a new warning does not fail the build; only a new ERROR does.** (ci.yml's lint-step comment still says "two warnings are known and tracked" — **stale as of this measurement**; there are none. That comment is outside this pass's ownership.) **The zero is a property of the tree today, held by nobody. If you want it enforced, that is a change to ci.yml, not a re-reading of it.**
- **A bug-fix PR must include a test that would have caught it.** Tests live next to code (`pipeline.ts` → `pipeline.test.ts`); no `__tests__/` tree.
- **MUTATION-VERIFY CULTURE: an assertion is not verified until reverting the code turns it red.** State the count when you claim it ("N reverts, N failures, 0 vacuous"). A suite that stays green against the bug it names is the defect, not the evidence.
- **A PIN ON A SYMBOL IS NOT A PIN.** Asserting a constant is *referenced* stays green while its VALUE is rewritten out from under the thing it must match. Pin the value, on both sides of any join with no shared module.
- **A REGEX OVER SOURCE TEXT IS NOT A BEHAVIOURAL ASSERTION.** It goes red on a refactor that changed nothing and green on a path that does the wrong thing. Drive the real function.
- **Assert the object that CROSSES the process boundary**, not the function that computes it (§11).
- **A comment asserting where a filter lives is not evidence the filter exists.** When a comment says a constraint is enforced somewhere else, open that somewhere else.
- **A MIXED TEST FILE WHOSE FEATURE IS DELETED IS REWRITTEN DOWN TO WHAT SURVIVES, NOT REMOVED** — deleting one whole has twice taken an unrelated live guard with it.
- **Executable authorities to prefer over prose:** `src/shared/auth/write-gate-coverage.test.ts` (the three auth gate sets), `dopl-desktop-app/test/ui-sync-tables.test.mjs` + `ui-sync-replica-identity.test.mjs` (publication + replica identity), `packages/mcp-server/src/strict-args.test.ts` (strict tool args), `test/removed-vocabulary.test.mjs` (no dead module, no dead require, every surviving mention annotated as history), `test/eslint-config-coverage.test.mjs`, `test/preload-parity.test.mjs`, `test/deep-link-target.test.mjs`, `test/prompt-profile-drift.test.mjs`.
